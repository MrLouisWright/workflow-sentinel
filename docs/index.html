workflow-sentinel

Catch insecure GitHub Actions workflows before they're merged.

Reads your .github/workflows/*.yml and action.yml files and flags the patterns behind most real-world Actions compromises: mutable action tags, over-privileged tokens, pull_request_target "pwn requests", script injection, leaked secrets and more. --fix pins your actions to commit SHAs for you.

$ npm i -D workflow-sentinel
Read the docs View on npm Source on GitHub

01 The problem

A workflow file is code that runs with your repository's tokens and secrets. One mutable action tag, one pull_request_target that checks out the PR head, or one ${{ github.event.issue.title }} in a run: step is enough for an attacker.

workflow-sentinel lints every workflow and composite action in the PR, with file and line numbers and a concrete fix, and can pin every action to a SHA automatically.

02 Features

01

Pwn-request detection

pull_request_target / workflow_run jobs that check out untrusted PR code.

02

Script injection

Untrusted event fields pasted into run: or actions/github-script.

03

Pinning, automated

Flags tag- and branch-pinned actions; --fix rewrites them to commit SHAs with Dependabot-compatible comments.

04

Token permissions

write-all, missing permissions blocks and persisted checkout credentials.

05

Secrets exposure

Secrets in jobs that run PR code, echoed secrets and secrets: inherit.

06

Cache & artifact poisoning

Tainted cache keys and risky artifact upload / download patterns.

07

Expression & schema checks

Mistyped contexts, unavailable properties, unknown keys and likely input typos.

08

Allowlists & inline ignores

Per-rule severities, expiring allow entries and # workflow-sentinel-ignore comments.

03 Usage

# Scan the current repo

$ npx workflow-sentinel

# One file, stricter gate

$ npx workflow-sentinel .github/workflows/release.yml --fail-on medium

# Trust first-party owners

$ npx workflow-sentinel --trusted-owner actions --trusted-owner github

# Pin every action to a SHA

$ GH_TOKEN=... npx workflow-sentinel --fix

04 CI / GitHub Action

name: Workflow security
on: [push, pull_request]
permissions:
  contents: read
  security-events: write
jobs:
  workflow-sentinel:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@11d5960a326750d5838078e36cf38b85af677262 # v4
        with: { persist-credentials: false }
      - uses: MrLouisWright/workflow-sentinel@v1
        with:
          fail-on: high
          sarif: workflow-sentinel.sarif
      - if: always()
        uses: github/codeql-action/upload-sarif@v3
        with: { sarif_file: workflow-sentinel.sarif }

05 Options & flags

FlagDescription
[paths…]Files or directories to scan (default: .github/workflows plus every action.yml)
--fail-on <sev>critical, high (default), medium, low, info or none
--config <file>Config file path
--trusted-owner <o>Allow tags for an owner (actions) or a repo (github/codeql-action). Repeatable
--fix / --fix-dry-runResolve each tag or branch to its commit SHA via the GitHub API and rewrite uses:
--json [file], --sarif <file>, --markdown <file>Reports
--no-fixes, --no-colorText output tweaks
